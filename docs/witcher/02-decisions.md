# Ведьмак: Старый мир — журнал решений

Решения там, где книга правил молчит или компьютерная версия требует выбора. Каждое — с местом в коде.

| Дата | Решение | Почему | Где |
|---|---|---|---|
| 2026-11-20 | Если стопка монстров нужного уровня пуста и прогнанных этого уровня нет — берётся монстр ближайшего уровня ниже | База.md с. 26 описывает только пополнение из прогнанных; без этого поле пустело и партия вставала (видно в партиях ботов впятером) | `shared/engine/fight.mjs` `spawnMonster` |
| 2026-11-20 | Тип атаки монстра выбирает соперник против часовой стрелки от активного (боты — случайно); соло — кубик 1–3 удар, 4–6 укус | База.md с. 24, 33 | `fight.mjs` `monsterTurn` |
| 2026-11-20 | Отмена: игрок сам отменяет своё действие, если оно не открыло скрытую информацию (ГСЧ не сдвинут, колоды не уменьшились); всё остальное — только хозяин стола | Как в Nemesis: отмена не должна позволять «переигрывать» броски и подсмотренные карты | `server.mjs` `revealedNothing` |
| 2026-11-20 | Игрок с неизвестным токеном во время партии занимает первое свободное место человека | Смена браузера/очистка хранилища не должна выкидывать из партии в LAN | `server.mjs` `join` |
| 2026-11-20 | Миниатюры красятся кодом (цвет школы; монстры — тёмная бронза с ободком цвета местности) | В `Witcher/` нет MTL-файлов (`Модели.md`) | `client/board.js` |
| 2026-11-20 | Последствия на карте исследования скрыты до выбора, затем открываются целиком (выбранное подсвечено, другое приглушено) | В настольной игре карту читает сосед справа (с. 16) — игрок не видит исходов заранее | `client/cards.js` `eventCard` |
| 2026-11-20 | «Переместитесь… затем можете выполнить её действие»: после события ход возвращается в окно фазы I только для действия новой локации и кнопки «Завершить → фаза III»; новое перемещение и битва недоступны | Текст карты разрешает ровно одно действие локации | `core.mjs` `options`/`turnCmd` (`t.afterExplore`) |
| 2026-11-20 | Задание выполняется командой игрока в фазе I (кнопка/Q), не автоматически | С. 17: выполнение необязательное, до или после действия локации | `core.mjs` `quest`, `explore.mjs` `questDone` |
| 2026-11-20 | Снаряжение — одно на всю партию: если «Кастет» уже у кого-то, эффект «возьмите событие 15» не срабатывает | Карта события существует в одном экземпляре | `explore.mjs` `eventFx` |
| 2026-11-20 | Пергамент карт событий — 92-й перцентиль яркости по 36 картам атласа (чернила всех карт выпадают) | Чистой рубашки/пустой карты в сканах нет | `tools/frames.mjs events` |
| 2026-11-20 | Карты исследования уникальны: разыгранная карта и карта задания уходят из игры навсегда; пустая колода — кнопка недоступна с причиной | Так в правилах (с. 16) и по просьбе пользователя; заменяет прежнее «под низ колоды» из среза | `explore.mjs`, `state.eventsUsed` |
| 2026-11-20 | Если в фазе II нечего сделать (событие запретило исследовать, нет монстра, медитация невозможна) — доступна кнопка «Пропустить фазу II» | «Обязаны выполнить одно из действий» (с. 13) выполнимо не всегда; без этого партия вставала | `core.mjs` `skipPhase2` |
| 2026-11-20 | Карты с неподдержанными эффектами не входят в колоды (список — `events-gen.mjs -v`), а не разыгрываются частично | Лучше меньше карт, чем неверные | `events-data.mjs` `UNSUPPORTED` |
| 2026-11-20 | Режимы «Кастомная» / «Игра на MMR» и три правила стола — по запросу пользователя (не из книги); выбор кастомных правил запоминается при переключении на MMR и обратно | Домашние правила пользователя | `rules-data.mjs` `HOUSE_RULES`, `server.mjs` |
| 2026-11-20 | Возврат эликсиров: после битвы (любой исход) выбираются выпитые в этой битве эликсиры, 1 золото за каждый, не больше, чем есть золота; эликсиры возвращаются игроку из сброса эликсиров | Правило стола пользователя | `fight.mjs` `elixirReturnAsk` |
| 2026-11-20 | Открытые последствия — чисто клиентская отрисовка: данные карт и так общие, скрытой информации нет | Карта печатная, известна всем | `client/prompt.js` |
