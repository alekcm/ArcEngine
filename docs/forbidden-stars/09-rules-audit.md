# Сверка движка с правилами: отчёт

Это отчёт о том, как движок Forbidden Stars в ArcEngine сходится с напечатанными правилами,
и чем именно это проверено. Модульных тестов игры в репозитории нет: они проходили при
неверных правилах, поэтому удалены. Их заменила построчная сверка — `tools/fs-audit.mjs`.

## 1. Как устроена сверка

1. Источник истины — `01-rules-reference.md`: текст `Rules Reference` из PDF, извлечённый
   машинно, без распознавания глазами. Каждая проверка **цитирует** строку оттуда.
2. Проверка строит в `node:vm` состояние ровно под этот случай: скрипты грузятся в порядке
   `index.html` (`FSData.js`, `FSEffects.js`, `FSRules.js`), доска собирается движком
   (`newReadyGame`) и затем чистится до нужного минимума.
3. Проверка смотрит, что движок сделал: числа, флаги, ошибки команд. Провал печатает
   «ждали … получили …».
4. Сверка не зависит от клиента и от сервера: только правила и данные.

```
node tools/fs-audit.mjs            все проверки
node tools/fs-audit.mjs combat     только те, в чьём имени или тексте есть слово
node tools/check.mjs               типы (tsc) + сверка правил — то же, что check.bat
```

Сейчас: **70 проверок, 0 провалов**. Ниже — что покрыто.

## 2. Что покрыто (по разделам Rules Reference)

| Раздел | Проверки |
|---|---|
| Планирование (Planning Phase) | `plan-1` … `plan-4`: куда можно класть жетон, четыре жетона за фазу, стек приказов, очередь активного игрока |
| Наступление (Advance Order) | `adv-1` … `adv-6`: только активная система, один сосед для войск, одна спорная область, корабли без пути, спорная область не часть пути, варп-шторм |
| Развёртывание (Deploy Order) | `dep-1` … `dep-5`: фабрика в системе, предел развёртывания, одна постройка, кеш −2, командный уровень и кузница |
| Стратегия и доминирование | `str-1` … `str-3`, `dom-1`, `dom-2`: условия покупки улучшений, лимиты, приказ на колоду событий, ресурсы с миров, три жетона каждого вида |
| Бой (Combat) | `combat-1` … `combat-15` (и `combat-9b`): кубики, предел восьми, деморализация, бастион в бою, мгновенная победа, урон, жетоны боя, карты до конца боя, три раунда, ничья в морали, трофеи, выбор раненого, излишек урона, подкрепления, колода боя, запрет пропуска карты |
| Отступление (Retreats) | `ret-1`, `ret-2`: куда нельзя отступать, уничтожение без пути |
| Вместимость, обновление, победа | `cap-1` … `cap-3`, `refresh-1` … `refresh-4`, `win-1`, `win-2`: выбор игрока сверх вместимости, конец приказа и конец фазы событий, материя, подъём деморализованных, шторм раз за фазу, карты за жетоны, цели и победа |
| Орбитальный удар | `strike-1` … `strike-3`: пустота и мир одной системы, бастион запрещает удар, урон не деморализует |
| Постройки, командование, бастионы | `cmd-1`, `cmd-2`, `struct-1`, `struct-2`, `bastion-1`, `bastion-2`, `asset-1`, `adj-1`: уровень = города, запрет покупки выше уровня, одна постройка на мир, постройки вне вместимости, бастион защищает один, бастион не деморализуется и не отступает, кеш не на улучшения, соседство только по общей границе |
| Движение | `mov-1` … `mov-3`, `rein-1`, `rein-2`: не больше пяти отрядов, корабли из соседней системы закрывают путь войскам из другой, деморализованный не двигается, предел жетонов подкрепления, жетоны не дают кубиков |
| Компоненты и траты | `comp-1`, `comp-2`, `spend-1`: постройка без жетона контроля уничтожается, покупка только из запаса, материя не уходит в минус |
| Тексты карт | `cards-1` … `cards-3`, `abil-1`: каждая боевая карта разыгрывается движком и за место нападающего, и за защитника; каждая карта события, каждое улучшение приказа и каждая из 12 способностей фракций разыгрывается; у каждого шага, который называет текст карты, есть обработчик в движке |

Отдельно `tools/fs-coverage.mjs` считает, сколько предложений текстов карт движок читает:
**100 %** (92 % становятся правилом, 8 % — пояснения правил, которые движок показывает игроку).

## 3. Что было найдено и исправлено

Сверка нашла расхождения, которых не видели прежние тесты. Каждое исправлено в движке
(`js/fs/FSRules.js`, `js/fs/FSEffects.js`) и закрыто проверкой:

| Правило | Что было не так |
|---|---|
| «he must destroy units of his choice in that area» | отряды сверх вместимости уничтожались автоматически, без выбора игрока; убирался только активный игрок |
| «checked … at the end of each Event Phase» | конец фазы событий не проверял вместимость вовсе |
| «A player can exceed … but can never end the movement with more than five units in a single area» | шестой отряд вставал в область: предела в пять не было |
| «Retreating units must move to a friendly area … or an uncontrolled area» | отступление разрешало пустоту и чужой мир |
| «If there is no area for a unit to retreat to, that unit is destroyed» | без пути отряды оставались на месте |
| «After resolving a retreat, he must destroy units of his choice» | после отступления лишние отряды не спрашивались |
| «If the defender does not have unrouted units or bastions … the attacker immediately wins» | бастион не считался защитником, бой начинался с пустым защитником |
| «When the attacker wins a battle, he takes control of all structures remaining on the world» | трофеи переходили не только нападающему и не все |
| «If a player would acquire a new structure … he does not have an available structure control token, that structure is immediately destroyed» | трофейная постройка выдавалась без жетона контроля |
| «use these values as if it were a unit» (бастион) | бастион не давал своих кубиков и морали в бою |
| «An orbital strike cannot be resolved against a world containing a bastion» | удар по миру с бастионом проходил; урон с орбиты к тому же деморализовал |
| «The maximum number of reinforcement tokens … equal to the number of plastic units» | предел жетонов считался неверно (бастионы и жетоны путались с отрядами) |
| «Retreats» — кто отступает и куда | защитник мог отступить в систему, откуда пришли нападавшие |
| текст карты, называющий отряд | боевые карты разбирались без фракции: «разместите К'тана» не находило отряд |
| «Нельзя пропустить боевую карту» | `skipCard` должен отвергаться — и отвергается; проверка `combat-15` |

Отдельно — ошибка механизма эффектов, а не правила: вопрос внутри ветки `choice` после ответа
переспрашивался заново с другой ветки, и партия зацикливалась (сид 2, «Какие отряды
деморализовать?»). Исправлено полем `pending.choice`; сверка партий ботом: 16 партий
(2–4 игрока, сиды 1–16) доходят до победителя.

## 4. Чего сверка не доказывает

Честные границы:

- **Толкование текста карты.** `cards-1` доказывает, что карта разбирается в шаги и шаги
  разыгрываются без ошибок, но не то, что толкование совпадает с замыслом автора карты.
  Смысловой разбор — `04-combat-cards.md` (транскрипция) и `fs-coverage.mjs` (сколько
  предложений читается).
- **Визуальную часть** (доска, стол боя, карты, кубики) сверка не трогает: её свидетель —
  глаза пользователя.
- **Редкие сочетания карт** проверены только по одной карте за раз; взаимодействия карт
  проверяются партиями ботов, а не перебором.

Вердикт: правила, перечисленные в разделе 2, движок выполняет; расхождения из раздела 3
закрыты. Дальше сверка расширяется так: новое правило в движке — новая проверка с цитатой.
