Приоритет: конкретный текст карты/комнаты, затем предоставленные правила Redux; `Атака.txt` уточняет **количество экземпляров**. Базовая Nemesis не подменяла местную версию.

- `Nemesis/Колоды/Атака.txt`, лицевые стороны и обороты Action/Attack/Queen/Event/Serious Wound/Item/Support/Feat/Computer/Adaptation/Field Data/Objective/Starter/Quest.

**Обозначения:** **OK** — проверено, поведение совпадает; **T** — есть исполняемый тест в `nemesis/tools/audit.test.mjs` (все проходят); **U** — глубоко не проверено; **C** — противоречие/неоднозначность самих материалов. OCR использовался только для навигации; спорные значки перечитывались по изображениям.

## 3. Найденные дефекты и их исправление

Раздел фиксирует, что именно было не так до правок и чем это закрыто. Все перечисленные ниже сценарии входят в suite и проходят.

### A01 — Очередь обгоняла обязательные эффекты · было P0 · T
Меню хода ставилось перед уже запланированными шагами. Теперь `turn.choose` откладывает себя в конец очереди, пока в ней есть другие шаги (`turn.mjs`). Закрыты Archives → Field Data, карта здоровья Королевы и проверка рук.

### A02 — Финальная Infection/Eclosion · было P0 · T

### A03 — Секретные данные · было P0 · T

## 5. Что и как запускалось

```sh
node --test --test-reporter=tap nemesis/tools/audit.test.mjs   # 94 tests: 94 pass, 0 fail, exit 0
node tools/check.mjs                                          # типы + 89/89 тестов ArcEngine
node nemesis/tools/fuzz.mjs 300                               # 300 партий, 0 сбоев
node --check <каждый .mjs в nemesis/>                         # синтаксис без ошибок
```

До исправлений тот же suite давал `14 pass / 75 fail` (exit 1), причём все падения были `AssertionError` — то есть расхождения правил, а не падения движка.

### Границы

- Браузерный клиент, WebSocket-синхронизация и undo **не проходили E2E**; проверялся JSON-view, а не вёрстка.
- Fixtures частично синтетические: 94 сценария не заменяют исчерпывающий перебор комбинаций.
- `node:test` останавливается на первом падении assertion, поэтому зелёный прогон подтверждает сформулированные утверждения, а не всю подсистему.
- Fuzz проверяет достижимость завершения и сериализацию, а не правильность правил.
- «Не упало» ≠ «совпадает с настольной версией»: метки **U** оставлены честно.

## 6. Противоречия источников и снятые подозрения

1. **Computer с Malfunction.** Общий запрет (стр. 1/16/19) против формулировки RoomSheet. Server Room — напечатанное исключение для целевой Room Action, а не разрешение любому Computer.
2. **Количество Additional Rooms:** заголовок RoomSheet говорит 10, перечислено 11; в коде 11 определений.
3. **Bulkheads Open:** на карте открытие дверей стоит выше движения, общий порядок стр. 4/24 — движение первым. Реализация следует общему порядку.
4. **Event targeting:** стр. 8 говорит о всех картах в руке, карта события печатает значок Action card. Выбран приоритет конкретной карты (`EVENT-06`).
5. **Третья Serious Wound:** на Dashboard 3+3+3 клетки и отдельная клетка перед черепом; трактовка «третья травма всегда убивает» не навязывается. Подтверждённая ошибка нулевого здоровья исправлена отдельно.
6. **BFF/Heroic Escape, «on board».** В escape-ветке не решено, означает ли это корабль или ту же капсулу; BFF-hibernation исключение читается однозначно и проверено.
7. **Knowledge за Computer.** Стр. 17.2 говорит об «applicable Computer Action»; код начисляет +1 за каждое действие компьютера.
8. **Не ошибки (проверено и оставлено):** Tail 1/2 различны; числовой результат ≤ Queen Hits действительно критический; доплаты четырёх Field Data централизованы; Safety in Numbers требует второго персонажа; запрет armor для тяжело раненого; Energy Charge даёт 3 патрона; у Interruption есть автоматика, несмотря на устаревший текст данных; Respite явно разрешает Андроиду игнорировать Synthetic.
